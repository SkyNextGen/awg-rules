# Источники мессенджеров и Discord UDP

Telegram, WhatsApp и Discord остаются отдельными обновляемыми custom-источниками в config/sources.json. На каждом запуске сборщик получает V2Fly, Discord и Telegram дополнительно получают ITDog Services. Их отдельные JSON сохраняются в dist/custom; единственный итоговый бинарный набор — dist/routing.srs.

## Discord: файлы, медиа и голос

Домены Discord из V2Fly и ITDog покрывают discord.com, discord.gg, discordapp.com, discordapp.net, discord.media и поддомены. Google включён целиком, включая storage.googleapis.com для загрузки вложений.

Проверяемый источник портовых правил: https://github.com/itdoginfo/allow-domains/blob/main/convert.py

- UDP 50000:65535 совместно со списком https://raw.githubusercontent.com/itdoginfo/allow-domains/main/Subnets/IPv4/discord.lst
- Тот же UDP-диапазон со списком https://raw.githubusercontent.com/itdoginfo/allow-domains/main/Subnets/IPv6/discord.lst. Распространение портового ограничения на IPv6 — наше явно обозначенное допущение: upstream публикует IPv6-список, но сам convert.py включает только IPv4.
- UDP 19000:20000 совместно с 104.16.0.0/12, как в convert.py. Проверка CIDR строгая: изменение требует повторного аудита.

Сборщик читает портовые ограничения из AST upstream, не выполняя его код. Любое исчезновение UDP, портов или ожидаемой структуры останавливает сборку. Правила хранятся отдельными элементами rules: network AND ip_cidr AND port_range. Они не попадают в общий ip_cidr без портов.

## Ограничения

Это правила сообщества ITDog, а не официальный перечень всех голосовых серверов Discord. Подсети генерируются из iplist.opencck.org и включают общие сети Google/Cloudflare. Даже при ограничении UDP-портов возможен захват чужого трафика на совпадающих портах.

Официальная документация https://docs.discord.com/developers/topics/voice-connections определяет IP и UDP-порт в runtime Ready payload, а результаты voice server discovery не рекомендует кэшировать. Статический список не гарантирует все текущие endpoints. Отдельного подтверждённого IPv6-правила для низких портов Cloudflare в convert.py нет: не выдумываем его и не расширяем ASN.

Доменные правила работают при доступном имени (DNS mapping/sniffing). Голосовой поток к IP без имени зависит от scoped UDP. Итоговую совместимость AWG Manager и реальные звонки нужно проверить отдельно: compile/decompile проверяет формат sing-box, но не интеграцию клиента.

Все AI означает весь текущий состав выбранных V2Fly category-ai-cn, category-ai-!cn и category-ai-ru с рекурсивными include; неизвестные или ещё не добавленные upstream сервисы автоматически не обнаруживаются.

## ITDog и расписание

Create lists: понедельник 08:29 UTC. Create subnets: понедельник 07:16 UTC. Источники: .github/workflows/create-lists.yml и create-subnets.yml в ITDog.

Плановые запуски реально происходят: 05.10.2026 списки успешно опубликованы к 17:18:56 UTC, подсети — к 16:02:08 UTC. На 28.09.2026 сборка подсетей завершилась ошибкой; списки при этом успешно обновились. История проверена через GitHub Actions API 11.10.2026.

Наша Action: ежедневно 20:17 UTC / 23:17 МСК. Это 11 ч 48 мин после cron ITDog и почти 3 часа после последней наблюдавшейся публикации. Проверка src/check_itdog.py требует успешного завершения ОБОИХ плановых workflow в текущей неделе и 10 минут на распространение. Если upstream задержался или упал, сборка прекращается до публикации и сохраняет прежний dist; повторная проверка выполняется следующим ежедневным запуском. workflow_dispatch и существующие тесты, compile/decompile и уведомления сохранены. Проверка свежести применяется только к schedule: ручной запуск и push могут собирать последнюю доступную опубликованную версию.

## Локальная проверка

Сетевые источники получены 11.10.2026 через доступный сетевой инструмент и сохранены в .review-cache с URL, временем и SHA256. Локальный Python не имеет рабочего DNS в изолированной среде; SOURCE_CACHE явно включает сборку из проверенной копии. Сборщик проверяет SHA256 и ограничивает возраст копии 24 часами. В обычной Action SOURCE_CACHE отсутствует и источники читаются по HTTPS. Официальный sing-box 1.12.12 проверен по SHA256 релиза.
