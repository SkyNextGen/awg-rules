# 🧭 AWG Rules
### Личный набор маршрутизации для AWG Manager · TProxy · sing-box

[![Сборка](https://github.com/SkyNextGen/awg-rules/actions/workflows/build.yml/badge.svg)](https://github.com/SkyNextGen/awg-rules/actions/workflows/build.yml)
[![Отчёт](https://img.shields.io/badge/отчёт-последняя_сборка-blue)](dist/report.md)

**Один файл для выбранных сервисов через VPN.** GitHub Actions получает домены и IP из проверяемых источников, объединяет их, убирает повторения и публикует готовый `routing.srs`.

> Набор предназначен для AWG Manager в режиме **TProxy**. Он содержит условия выбора трафика. VPN-подключение и направление трафика в нужный outbound настраиваются в AWG Manager.

## 🌐 Откуда берутся домены и IP

| Часть набора | Источник | Как обновляется |
|---|---|---|
| ITDog | [Russia/inside-kvas.lst](https://github.com/itdoginfo/allow-domains/blob/main/Russia/inside-kvas.lst) | Загружается целиком на каждой сборке |
| Категории сервисов | [V2Fly domain-list-community](https://github.com/v2fly/domain-list-community/tree/master/data) | Выбранные категории и их `include` на каждой сборке |
| Telegram | V2Fly + [ITDog Services](https://github.com/itdoginfo/allow-domains/blob/main/Services/telegram.lst) + [официальные CIDR](https://core.telegram.org/resources/cidr.txt) + BGP Telegram | Домены и сети пересобираются на каждой сборке |
| WhatsApp | V2Fly + BGP Meta | Домены и сети пересобираются на каждой сборке |
| Discord | V2Fly + [ITDog Services](https://github.com/itdoginfo/allow-domains/blob/main/Services/discord.lst) + [подсети](https://github.com/itdoginfo/allow-domains/tree/main/Subnets) и [портовые правила ITDog](https://github.com/itdoginfo/allow-domains/blob/main/convert.py) | Домены и UDP-правила пересобираются на каждой сборке |
| Личные дополнения | [custom-domains.txt](config/custom-domains.txt), [custom-ip-cidrs.txt](config/custom-ip-cidrs.txt) | Редактируются вручную |

**BGP** — опубликованные маршруты IP-сетей. Разрешены только ASN Telegram **62041, 62014, 59930, 44907, 211157** и Meta **32934, 63293**. Сети Meta общие для компании: они не являются отдельным реестром IP WhatsApp.

Сборщик сначала обращается к **RIPEstat**, при сбое — к [bgp.tools/table.jsonl](https://bgp.tools/table.jsonl), затем может использовать предыдущий проверенный снимок возрастом до **8 дней**. Использование старого снимка отражается в предупреждениях; дата его получения не обновляется.

IP не вычисляются из DNS-ответов доменов. Общие ASN Google, Cloudflare, Amazon и других CDN автоматически не добавляются. В личном списке IP есть вручную разрешённые сети общего хостинга/CDN: они могут направлять через VPN и сторонние сервисы. Личные домены с именами Telegram/WhatsApp также не являются подтверждением принадлежности этим компаниям.

## 🧩 Как сокращается список

| Входные записи | Результат |
|---|---|
| `google.com` и `clients6.google.com` как suffix | Остаётся `google.com`: он уже покрывает поддомен |
| Два одинаковых домена из разных источников | Одна запись |
| Exact-домен, уже покрытый suffix | Exact-запись удаляется |
| Вложенные или соседние IP-сети | Объединяются без добавления новых адресов |

**Suffix включает сам домен и все его поддомены.** Он совпадает по границам имени: `example.com` покрывает `a.example.com`, но не `notexample.com`.

V2Fly `full:` сохраняется как точное совпадение; `keyword:` и `regexp:` сохраняют свой тип. Неизвестные конструкции и фильтрованные `include` останавливают сборку.

Количество записей уменьшается за счёт объединения. Жёсткого лимита «5000 доменов» нет; защитный максимум — **100 000 доменных правил**. Сумма строк источников в отчёте может превышать итог, поскольку источники пересекаются.

## 🎙️ Особенность Discord в TProxy

Голосовые правила хранятся отдельно. Для совпадения должны одновременно выполняться **протокол UDP + IP из списка + порт назначения**.

| Порты UDP | IP-условие |
|---|---|
| `50000–65535` | Списки Discord IPv4 и IPv6 от ITDog |
| `19000–20000` | `104.16.0.0/12`, как в преобразователе ITDog; только IPv4 |

Сборщик читает структуру портовых правил ITDog без выполнения чужого кода. Потеря UDP, портов или ожидаемой структуры блокирует публикацию.

> **Сохраняйте ограничения портов.** Перенос этих подсетей в обычный IP-маршрут расширит совпадение на весь трафик к ним.

Распространение верхнего диапазона портов на IPv6 — допущение этого проекта: ITDog публикует IPv6-список, но его преобразователь использует IPv4. Подтверждённого IPv6-правила для нижнего диапазона нет.

Это списки сообщества, которые включают общие сети. Возможен захват стороннего UDP на тех же портах; полный охват текущих голосовых серверов не гарантируется. [Discord выдаёт IP и порт во время соединения](https://docs.discord.com/developers/topics/voice-connections).

Доменные условия требуют доступного имени через DNS/sniffing. Перехват IPv6, исключения UDP-портов и реальные звонки проверяются отдельно на устройстве.

## 🔄 Когда и как обновляется

**Ежедневно в 23:17 МСК**, вручную через Actions → **Build routing rules → Run workflow**, а также после изменений кода, настроек или тестов в `main`. GitHub может задерживать запуск по расписанию.

1. Запускаются тесты. Для плановой сборки дополнительно проверяются успешные публикации обоих недельных workflow ITDog и 10 минут на распространение.
2. Загружаются источники, объединяются домены/IP и создаются отдельные наборы мессенджеров.
3. Официальный **sing-box 1.12.12** компилирует JSON в SRS и обратно. Архив sing-box проверяется по SHA256; формат rule-set — **version 1**.
4. Проверяются размеры, сети, покрытие ключевых сервисов и сохранение UDP-условий.
5. При успехе весь `dist` публикуется одним коммитом, затем отправляется отчёт в Telegram.

Проверка PR выполняет сборку без публикации и Telegram. Коммиты с готовыми результатами не запускают сборку повторно.

### Если сборка остановилась

Ошибка источника, небезопасные сети, потеря покрытия или недопустимое изменение размера блокируют публикацию. **Последний успешно опубликованный набор остаётся доступен.** Следующий запуск заново пробует получить источники.

Основные пороги в [sources.json](config/sources.json): минимум 500 доменов ITDog и 500 в итоге, максимум 20 000 общих IP-префиксов. Сокращение общего числа правил более чем на 20% или рост более чем на 50% требует проверки; при добавлении новых доменных источников допускается рост до трёх раз. BGP проверяется дополнительно по каждому ASN и обоим семействам IP.

Ошибка доставки Telegram не отменяет успешную публикацию. Отчёт показывает дельты доменов, IPv4/IPv6, изменившиеся источники и динамику последних 7 успешных запусков.

## 🛠️ Что редактировать

| Задача | Файл |
|---|---|
| Добавить сервис из V2Fly | [config/v2fly-categories.txt](config/v2fly-categories.txt): имя категории, одна на строку |
| Добавить личный домен | [config/custom-domains.txt](config/custom-domains.txt): домен без URL, пути и порта; все записи — suffix |
| Добавить личную сеть или адрес | [config/custom-ip-cidrs.txt](config/custom-ip-cidrs.txt): строгий CIDR; одиночный IPv4 — `/32`, IPv6 — `/128` |
| Изменить upstream, расписание или проверки | [config/sources.json](config/sources.json), [.github/workflows/build.yml](.github/workflows/build.yml) |

Перед добавлением сравните запись с текущими источниками с учётом суффиксов и CIDR. Широкий родительский домен может захватить другие сервисы; проверяйте смысл расширения. Когда upstream уже покрывает custom-домен, проверка выводит уведомление, но самостоятельно не редактирует личный файл. Итоговый набор всё равно объединяет повторения.

| `dist/` | Готовый набор, отчёты, история и снимки для сравнения |

Отдельные JSON мессенджеров уже включены в `routing.srs`; для общего набора достаточно одного URL. `dist/report.json` хранит полные дельты и SHA256, `dist/source-snapshot.json` — предыдущие записи источников, `dist/bgp-snapshot.json` — данные BGP, `dist/history.json` — последние 52 успешные сборки.

### Telegram

В GitHub **Settings → Secrets and variables → Actions** задайте `TG_BOT_TOKEN` и `TG_CHAT_ID`. Без обоих значений доставка пропускается. Токен хранится только в Secrets.

## 🧪 Локальная проверка

Нужны **Python 3.12+** и доступ к источникам по HTTPS. Сторонние Python-библиотеки не требуются.

```sh
python -m unittest discover -s tests -v
python src/install_sing_box.py
SING_BOX=.tools/sing-box python src/build.py
python src/check_service_coverage.py
```

В Windows PowerShell перед сборкой:

```powershell
$env:SING_BOX = "$PWD\.tools\sing-box.exe"
python src/build.py
python src/check_service_coverage.py
```

Для локальной проверки можно явно задать `SOURCE_CACHE`: сборщик принимает копии HTTPS-источников с проверяемым SHA256 и возрастом до 24 часов. Обычный GitHub Actions получает источники напрямую.

## 🤝 Для человека или другого Work

- Этот репозиторий создаёт **данные маршрутизации**. Настройки сервера и роутера находятся вне него.
- Состав меняйте в `config`; `dist` обычно пересоздаёт сборщик.
- Сохраняйте типы совпадения V2Fly, границы суффиксов, проверку сетей и ограничения портов Discord.
- После изменения нужны тесты, полная сборка, compile/decompile и проверка покрытия. Успешная проверка формата не доказывает работоспособность звонка на конкретном клиенте.
- После слияния проверьте Action в `main`, публикацию и результат доставки Telegram.
- История решений и удалённых файлов доступна в git; текущая документация собрана в этом README.

**Проверка на устройстве:** загрузка SRS, открытие нужных сайтов, Discord-вложения и звонки, загрузки Nexus, IPv6. Для отката верните предыдущий URL в AWG Manager или восстановите проверенный `dist` отдельным коммитом.
